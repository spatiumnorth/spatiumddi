### Fixed

- A role granted one DNS resource type no longer reads the rest of DNS: each `/api/v1/dns` route now needs a grant on the type it serves (server groups, servers, options, views, ACLs and TSIG keys `dns_group`; zones and their settings `dns_zone`; records, imports and the DNS tools `dns_record`), so a role with only "read DNS server groups" or "read DNS records" no longer lists every zone, server and group. Routes that return several types, such as a zone export or the zone drift report, need each of them, and the Copilot DNS tools, the DNS traffic chart and tag search follow the same rule. **Behaviour change on upgrade:** a custom role that relied on one DNS grant to read the rest loses those reads — add `read` on each type it should see (usually `dns_group`, `dns_zone` and `dns_record` together; the DNS page starts at the server groups). Writing a record now needs `write` on `dns_record` (it used to accept `write` on any DNS type). API tokens bound to a zone keep reaching that zone, its group and its records. The built-in roles keep their access; Auditor and Compliance Editor now list `read` on DNS server groups and records explicitly (#3073).
