### Fixed

- The DNS agent drained a long record-op queue at 61 to 76 ops a second whatever the hardware: for every 5,000-op page it re-downloaded, re-parsed and re-saved the whole config bundle it already held (250 MB at 1M devices), applied each op as its own RFC 2136 UPDATE, and ran the all-zones served-serial read between pages. An agent whose live bundle is the one it presents now says so (`X-Spatium-Ops-Only`) and gets the ops page alone, and one that is sent the body anyway reads only its head; consecutive ops of a zone share one UPDATE (a failed one falls back to op by op, with the same per-op errors); the TSIG key is parsed once; and the served-serial read waits, for at most 10 minutes, while ops are draining. Older agents are answered exactly as before. (#5025)
