### Fixed

- Adding a DNS view to a BIND9 group no longer loads every zone again in the new view. If a zone's copy is identical across views (no view-scoped records, the same options and the same view `allow-query`), it is now loaded once and referenced from the other views with BIND's `in-view`, so named's memory grows with distinct zone data rather than with views × data. Blocklists are the exception: BIND cannot share a response-policy zone between views, so each view that applies a list still loads its own copy, at about 1.4 kB per entry. To make that cost visible before it OOM-kills a group, each BIND9 agent now reports its container's memory limit on the heartbeat (migration `d8f3a61c2e47`), and the control plane estimates each group's named memory against that limit. At 80 % of the limit it warns on the group, view and blocking-list API responses, in a banner on the group's Views and Blocking Lists tabs, through the new default-on `dns_memory_pressure` alert, and in the Copilot's `get_dns_group_memory_estimate` tool. The DNS and topology docs give the per-view cost (#3551).
