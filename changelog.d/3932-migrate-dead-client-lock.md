### Fixed

- An upgrade no longer hangs for hours behind a database session whose client has died. PostgreSQL now probes silent peers with TCP keepalives, so a dead client's session is dropped in about two minutes, and ends a session left idle in a transaction for an hour (CloudNativePG, the in-chart Postgres, Docker Compose and `k8s/ha`; reloads for CNPG, one restart for the in-chart and Compose Postgres). The migrate command bounds each lock wait with `lock_timeout`, logs which session holds the lock, ends stale idle-in-transaction sessions of the app's role that block it, and keeps retrying, so a migration behind a running backup still waits it out.
