### Fixed
- Deleting a DNS server group now removes its id from every IP space, block and subnet that referenced it (Trash included), so Edit Subnet no longer shows "Inheriting from parent: 1 group(s)" and the effective DNS no longer returns a deleted group. A migration cleans ids already stranded by earlier deletes, and creating or editing a space, block or subnet, or validating or applying a subnet plan, now refuses a DNS server group id that does not exist (422, or a plan conflict) instead of storing it.
