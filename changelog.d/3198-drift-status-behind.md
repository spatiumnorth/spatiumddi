### Fixed

- **The zone Drift report no longer calls a server `ok` that is not serving the zone as saved (#3198).** A server's status meant only that the zone transfer worked, so a server stuck below the zone's serial, or missing saved records, read `ok`. A server that transferred is now `ok` only when nothing saved is missing, nothing extra is served and it is at the zone's serial; `behind` when saved records are missing or it sits below the serial for more than two minutes, `drift` when it also serves records SpatiumDDI does not hold. A failed transfer is still `error` / `unsupported`. The Drift tab, the API (new `reason`, `current_serial`, `target_serial`) and the `find_dns_zone_drift` copilot tool all carry it.
