### Fixed

- **The request portal now runs the same checks as the normal creates, at submit and at approval (#3243, #3244, #3245, #3248, #3249, #3250).**
  An address request that the manual create refuses (a name already taken in the zone, a MAC already recorded in the space, an address inside a DHCP dynamic pool, a private address in a public-facing zone, a name too long for its zone) is refused when it is submitted, in words, instead of queuing and failing at approval. An address request with no hostname is held to the same MAC and dynamic-pool checks at approval. A subnet request is checked at submit for a malformed or unknown template and for a Required subnet custom field no template or block supplies. A DNS record request with a priority, weight or port its type does not take is refused in the record create's words, and the approver no longer reads a text promising fields that are dropped. A `static_dhcp` address request is refused at submit, and fails at approval with nothing created, when no single DHCP scope serves the subnet, so no request ends provisioned without its reservation. The approver is no longer told an address recorded as available will fail the approval.
